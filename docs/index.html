fonctionnalités

Tout ce que pm2 monit ne te montre pas.

21 phases de développement, un seul dashboard. Chaque brique s'appuie sur le même flux temps réel — pas de système parallèle à maintenir.

Process en un coup d'œil

Statut, CPU, mémoire, restarts, uptime, mode fork/cluster. Start / restart / reload / stop en un clic, scale et hot-reload de la config sans passer par le terminal.

Logs en direct, sans latence

stdout/stderr streamés par WebSocket, comme pm2 logs mais dans le navigateur. Pause, recherche regex, coloration ANSI, export brut ou par période exacte.

regexansiexport

Log Explorer

Recherche full-text ou regex à travers plusieurs process et plusieurs serveurs en un seul appel, avec contexte avant/après et export streamé.

multi-processmulti-serveur

Dashboard global

Statut HEALTHY / WARNING / CRITICAL calculé automatiquement : système, process, alertes et timeline d'événements, en un seul coup d'œil au démarrage.

temps réel

Alertes & health checks

Seuils CPU/RAM/restarts avec cooldown et déduplication, plus des sondes HTTP/TCP/Command indépendantes du statut PM2 pour surveiller ce que PM2 ne voit pas.

seuilshttptcp

Auto-Healing

Redémarrage automatique d'un process qui crash en boucle, avec garde-fous configurables et journalisation de chaque intervention. Désactivé par défaut.

opt-in

Multi-serveur

Connecte plusieurs machines via des agents distants et surveille toute ta flotte PM2 depuis un seul écran — process, logs et recherche compris.

agents

Notifications multi-canal

Email, Discord, Telegram, Slack, webhook générique. Routing par règles depuis le moteur d'alertes, avec file d'attente, retry et déduplication.

emaildiscordslack+2

RBAC, clés API & audit

Permissions fines par app et par serveur, clés API scopées pour intégrer PM2 Monitor ailleurs, et un journal d'audit append-only de chaque action sensible.

installation

En route en trois commandes.

deploy.sh installe Node.js et PM2 si besoin, compile le frontend, configure nginx + HTTPS en option, et fait un rollback automatique si une mise à jour casse tout.

01 cloner le dépôt

Récupère le code

Un simple clone Git, aucune inscription ni token requis.

# sur ton serveur
git clone https://github.com/nogebeat/pm2-monitor.git
cd pm2-monitor
02 installer & démarrer

Un script, toutes les situations

Détecte ce qui est déjà en place, ne réinstalle rien inutilement. 

# installe, build, démarre sous PM2
chmod +x deploy.sh
./deploy.sh install
03 ouvrir le dashboard

Port 4200 par défaut

Accès direct par IP, ou derrière nginx + HTTPS si tu as fourni un domaine. 

# identifiants générés à l'install
open http://ton-serveur:4200
log explorer

Retrouve la ligne qui explique l'incident, pas dans dix onglets.

  • Recherche unifiée — full-text ou regex, sur un process, plusieurs process, ou plusieurs serveurs en même temps.
  • Filtres combinables — niveau (info/warn/error/debug), flux (stdout/stderr), plage de dates précise.
  • Contexte automatique — les lignes juste avant/après chaque résultat, sans changer d'écran.
  • Garde-fous intégrés — regex bornées et anti-ReDoS, limites de lignes scannées : jamais une requête non bornée.
